# Discord Bridge 5.6.0

Adds `/role_activity role:@Staff days:30 include_logs:true` for administrators to
search existing activity for members of a selected Discord role. The command
fetches complete current membership, including offline members, and reports
Discord/Minecraft event counts and last recorded activity in a downloadable CSV.
Members with no matching events are included. Optional event logs contain the
latest 10,000 matching records, with the included/total count shown explicitly.

Verified account links and administrative links take priority. Unlinked members
can match retained Minecraft player names against their current Discord names.
Name matches are labeled unverified; ambiguous names and conflicting links are
flagged for review. Reports do not modify links or saved activity.

The search uses the bridge's retained `discord.json` and `server.json` events,
including events recorded before upgrading. Reports remain available while
tracking is paused. Guild member retrieval is asynchronous, and report indexing
and CSV generation run off the server thread. Large files are gzip compressed.

Stop the main bridge server, replace its bridge wheel, and restart so the new
slash command synchronizes. Keep the bridge configuration, account links and
activity files. Child relay configuration and packages are unchanged.

Validation: 35 automated tests passed, covering saved-log loading, fresh member
retrieval, role filtering, account/name matching, ambiguous identities, private
admin access, date windows, log export limits and attachment handling. Real
Discord integration requires the configured bot and Server Members Intent.
The packaged wheel was also installed and imported with Endstone 0.11.15 on
Python 3.11; the role option and command parameter metadata were verified.
